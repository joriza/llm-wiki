## Tesis central

Clase de Fab Academy traducida a vídeo: panorama condensado (< 43 min) de cómo se usa la IA en 2026, centrado en programación y fabricación digital. La conclusión del canal: el «prompt perfecto» ya está pasado; el trabajo de este año es **context engineering** — darle al modelo, en su ventana de contexto, la información y las herramientas necesarias (memoria, instrucciones, wiki interna, skills, MCP) y **cerrar el bucle de feedback humano** (capturas de pantalla, reproducción de errores), porque los LLM «no ven» ni saben que se equivocan si nadie se lo hace llegar.

## Recorrido del vídeo

- **[02:16-07:09] Modelos**: los LLM son redes neuronales entrenadas sobre corpus masivos; pesos que codifican el entrenamiento. Cerrados/propietarios (GPT 5.0.4, Claude Sonnet/Opus 4.6, Gemini 3.1 Pro: API o suscripción, resultado espectacular, pero dependencia externa) frente a **abiertos** (Hugging Face: pesos descargables, sin límites de consumo, pero exigen hardware y funcionan algo peor; Qwen 3, DeepSeek, Mistral, Gemma 3.5). Herramientas de ejecución local: **Ollama** (ahora con app de escritorio y API compatible con Anthropic — puede sustituir el modelo de Claude Code por uno propio) y **LM Studio** (ya permite uso comercial; «la herramienta más cómoda hoy»). Pinocchio para probar generación de imagen/audio/vídeo.
- **[08:43-12:32] Destilación y límites**: destilar conocimiento de un modelo grande (pares Q&A, razonamiento) a uno pequeño; fine-tuning con Unsloth, LoRA/PEFT. Problema estructural: la arquitectura **transformer escala mal con el contexto** — duplicar el contexto cuadruplica el coste; y los pesos son estáticos, sin conocimiento posterior a la fecha de entrenamiento. Regla práctica: usar siempre el modelo más pequeño que dé el rendimiento necesario (20-30 tok/s frente a 2).
- **[12:32-16:36] Cómo superar los límites**: **in-context learning** (ejemplos en el prompt; ventanas actuales de 200k-1M tokens), **RAG** (contenido nuevo fuera de los pesos + recuperación; las herramientas ya ofrecen web grounding) y **fine-tuning** (adaptadores sobre el modelo base). Salidas estructuradas (JSON) ya estándar. Ejemplo real del canal en GitHub: **fabrag**, sistema RAG sobre el contenido de las lecciones y proyectos de Fab Academy, preservando autoría.
- **[16:36-20:04] De prompt perfecto a context engineering**: los modelos de 2026 detectan intenciones con mucho menos texto. Diagrama de Anthropic «context engineering for agents»: personalizar el prompt del sistema y seleccionar qué entra en contexto (documentos, fichero de memoria de interacciones previas, instrucciones, wiki interna). Los LLM no calculan: deciden llamar a herramientas (calculadora) cuando detectan que la petición lo requiere.
- **[20:04-23:03] Skills**: codificar tareas repetidas como carpetas `skills/` con un `SKILL.md` (instrucciones repetibles, aparecen como comandos) + **documentación de referencia y scripts ejecutables**; ejemplo del canal: skill que lanza el script hacia la cortadora láser, o skill que genera PDF con pandoc — «no le pides al modelo que lo vuelva a inventar cada vez; le dices: cuando toque, ejecuta este script».
- **[23:03-27:18] MCP**: estándar abierto de Anthropic ya soportado por casi todos; conecta el entorno de desarrollo con APIs, bases de datos, navegadores. En fabricación digital hay servidores para Blender, FreeCAD, Inkscape, Git, Docker. Experimento propio del canal: **MCP de Mods** (herramienta modular de Neil Gershenfeld para las máquinas de los fablabs) — con Claude Code Opus 4.6 se lo construyó «en un par de días» después de que en el encuentro de fablabs de Praga nadie lo supiera hacer; control por lenguaje natural de CNC, corte, impresión 3D.
- **[27:18-30:41] Herramientas del día a día**: **Cursor** (mini-RAG sobre la carpeta, marketplace de MCP, comparar la misma pregunta entre modelos; «mejor para trabajar con 3-4 repos a la vez, visualmente») y **Claude Code** (CLI, muy bueno pero caro: Pro 20 €/mes ≈ 1 hora de cada 5; Max con límites mensuales opacos; Team 200 €/mes).
- **[30:41-34:19] Spec-driven development**: Spec Kit y **OpenSpec** — definir requisitos, ejemplos y casos límite como Markdown, ejecutar la especificación, iterar, y **sincronizar la especificación base** al acabar para que refleje lo real. Flujo OpenSpec: `/opsx new` → fase explore (alternativas) → diseño → tareas → `/apply` → sync. OpenSpec admite esquemas personalizados (no solo código). Ver [[resumen-openspec-apps-full-stack-sin-codigo-vera-badias]] (tutorial completo del mismo flujo).
- **[34:37-36:02] Agentes y A2A**: agentes como LLM que ejecutan tareas autónomas; el estándar **A2A** (iniciado por Google, ahora Linux Foundation) conecta agentes entre sí. Ejemplo del canal: agente de diseño 3D → agente slicer → agente de impresora → agente de visión que supervisa la impresión. Whisper para dictar especificaciones por móvil y pasarlas a limpio.
- **[36:02-39:02] Reflexión: el feedback humano es el multiplicador**: el modo autónomo puro («Ralph mode»: agentes que se inventan el tooling) existe, pero lo que funciona mejor es darle al LLM el mismo feedback que necesitaría una persona: en Cursor/Claude Code se lanza el navegador, se piden capturas y se corrige el diseño en bucle; en depuración, el agente pone trazas, propone hipótesis de causa raíz y itera verificando con el humano.
- **[39:02-42:47] Contexto industrial y cierre**: la «guerra de licencias» de los últimos meses (acuerdo OpenAI-Disney con demanda a Google por entrenamiento) contrasta con las oportunidades de modelos MIT/Apache con datasets conocidos (**Olmo**). Cierre: herramienta + skills (codificar tareas) + ficheros de memoria (feedback acumulado) + MCP/agentes; apuesta por IA local «en tu infraestructura».

## Puntos clave

1. **Del prompt al contexto**: el año 2026 se resume en context engineering — elegir qué entra en la ventana (memoria, instrucciones, docs, wiki) y ofrecer herramientas para lo que el modelo no sabe hacer [18:25-20:04].
2. **Skills = tareas repetibles codificadas**, con scripts ejecutables incluidos; es la pieza más «aplicada» que sobrevivió del boom de interoperabilidad [20:04-23:03].
3. **MCP y A2A** como estándares abiertos que convierten al LLM en operador de aplicaciones reales (Blender, CNC, impresoras 3D); el propio canal construyó el MCP de Mods con Claude Code [23:03-27:18].
4. **Spec-driven development (Spec Kit/OpenSpec) evita el «se les va la olla»**: especificación viva sincronizada con el repo tras cada cambio [30:41-34:19].
5. **Cierre del bucle humano**: dar al agente el feedback que faltaría (capturas de pantalla, reproducir errores) acelera radicalmente la resolución; sin eso, el LLM improvisa [36:02-39:02].
6. **Coste cuadrático del contexto**: duplicar contexto = cuadruplicar coste; elegir el modelo más pequeño que funcione y destilar/fine-tunear para dominios concretos [10:25-12:32].
