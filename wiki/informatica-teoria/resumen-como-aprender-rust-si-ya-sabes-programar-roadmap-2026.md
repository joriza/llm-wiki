## Puntos clave

1. **El primer muro, como gancho** [00:00-00:31]: cuatro líneas de Python (tomar el primer elemento de una lista y añadir otro) que en Rust no compilan — «no puedes modificar la lista mientras tienes prestado uno de sus elementos»; en C++ el mismo código compila y «imprime un número que nadie ha escrito» (comportamiento indefinido); si te lanzas a async o a un framework web sin entender este error, «te lo vas a encontrar una y otra vez».
2. **Fase 1: herramientas y sintaxis básica** [00:31-02:37]: rustup instala rustc y Cargo (el equivalente de npm para JS o pip+venv para Python: crear proyecto, dependencias, compilar, tests); editor: VS Code con Rust Analyzer (o Zed, escrito en Rust); inmutabilidad por defecto (`let x = 5` no se reasigna sin `mut`); funciones, bucles, structs, enums y match — un switch que obliga a cubrir todos los casos; dos tipos de texto: `String` (propio, creciente) vs `&str` (vista prestada); los errores del compilador son largos porque explican la solución — acostumbrarse a leerlos desde el día uno; proyecto: el juego de adivinar el número del capítulo 2 del libro oficial (cargo + dependencia externa + match en una tarde).
3. **Fase 2: ownership — el muro grande** [02:37-05:38]: tres reglas: cada valor tiene un dueño; solo hay un dueño a la vez; cuando el dueño sale de bloque, el valor se libera — así Rust se ahorra el recolector de basura de Python/Java/Go (el compilador sabe antes de ejecutar dónde se libera cada cosa); consecuencias: la asignación mueve (valor movido — el original deja de valer; salida: clonar); préstamos con `&`: muchos lectores O un escritor, nunca ambos; **explicación del error del gancho**: un vector guarda sus elementos contiguos — al añadir uno que no cabe se muda y libera la memoria vieja, dejando la referencia apuntando «a la casa vieja» (exactamente lo que en C++ imprimía números raros); Rust no deja que ese programa exista; arreglo simple con números: quitar el ampersand (copiar); lifetimes como versión avanzada de lo mismo (el compilador casi siempre las deduce); tres trucos para pasar el muro: (a) leer el error entero y usar `rustc --explain N`; (b) clonar sin culpa mientras se aprende; (c) si se usa IA, pegarle el error para que lo explique pero escribir el arreglo uno mismo — «si solo copias el suyo, en el siguiente proyecto te vuelve a pasar»; proyecto: minigrep (capítulo 12) — buscador de texto de terminal con moves, préstamos, archivos, errores y la primera lifetime.
4. **Fase 3: quitar el acento del lenguaje de origen** [05:38-07:30]: sin excepciones — las funciones que pueden fallar devuelven `Result` (valor o error) y los datos que pueden faltar son `Option` (algo o nada); el compilador obliga a mirar ambos casos; `unwrap` como atajo peligroso (demo: pedir un archivo inexistente y el programa se cae — bien para probar, mal en producción); la salida idiomática es el operador `?` (una línea en lugar de cinco; el error sube a quien llama); traits («esto sabe hacer tal cosa») y genéricos; iteradores en cadena en lugar de bucle + lista vacía; herramientas que enseñan: rustfmt (formato), clippy («un compañero leyendo tu código por encima del hombro»); ecosistema: crates.io (librerías) y docs.rs (documentación); práctica con rustlings (ejercicios que no compilan y hay que arreglar); proyecto: sumador de gastos por categoría con condición — «ni un solo unwrap» (si falta el archivo o una línea viene mal, el programa lo dice y sigue).
5. **Fase 4: concurrencia sin miedo** [07:30-08:53]: el capítulo del libro se llama así «y el mérito es de la fase dos» — las mismas reglas de préstamos impiden que dos hilos escriban el mismo dato (la carrera de datos en Rust directamente no compila); demo: hilo que suma un contador desde dentro y otro desde fuera — el compilador frena («ese hilo podría seguir vivo cuando el contador ya no exista»); para compartir de verdad: `Arc` (varios dueños) + `Mutex` (entra de uno en uno), y el trait `Sync`; async/await: para programas que se pasan la vida esperando (red, BD, archivos) manteniendo miles de conexiones; Rust no trae el motor de serie — se elige, y el común es Tokio; el último muro: Tokio puede mover la tarea de hilo mientras espera, así que guardar en ella un dato no-enviable (`Rc`) no compila — la solución suele ser cambiar `Rc` por `Arc` o soltar el dato antes del await; entender este error exige las fases 2+3+4 juntas («si empiezas por aquí, este error no hay quien lo descifre» — async va al final); proyecto: el mini-Redis del tutorial oficial de Tokio (servidor + cliente pequeños).
6. **El cruce: aprender por camino** [08:53-10:06]: no hace falta aprenderlo todo — elegir camino y aprender solo lo que pide: backend (Axum sobre Tokio, Serde para JSON, SQLX para base de datos); herramientas de terminal (Clap para argumentos, Ratatui [ASR «Ratatouille»] para interfaces en consola); web en navegador (WebAssembly con wasm-bindgen); embebido (Embassy para microcontroladores — sin librería estándar, a veces con `unsafe`); cada camino con un primer proyecto enseñable: API de tareas con Axum, tu propia versión de una herramienta de terminal, un juego pequeño en el navegador, o hacer parpadear un LED.
7. **Recursos y cierre** [10:06-10:55]: empezar por el libro oficial — «El lenguaje de programación Rust», gratis y traducido al español por la comunidad hispana: leer hasta el capítulo 2 y hacer el juego de adivinar esta semana; alternativas gratuitas: Rust by Example (aprender con ejemplos) y Exercism (practicar con corrección); al atascarse — volver al error, leerlo entero y seguir, no reiniciar de cero; gancho al video anterior sobre Rust en la inteligencia artificial.
